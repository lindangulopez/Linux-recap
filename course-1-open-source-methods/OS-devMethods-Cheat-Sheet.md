# 🧾 **Open Source Development Methods — Cheat Sheet**

## **What is Open Source?**

* Code is open, modifiable, shareable
* Built on collaboration, transparency, community
* Benefits: innovation, security, lower cost, flexibility

---

## **Governance Models**

* **BDFL** — One key leader
* **Meritocracy** — Influence earned by contribution
* **Committee/Foundation** — Shared decision-making
* Maintainers manage direction; contributors support growth

---

## **How to Contribute**

* Communicate clearly and respectfully
* Start small: issues, documentation, tests
* Follow project guidelines (CONTRIBUTING, CODE OF CONDUCT)
* Use Git workflows: branches → commits → pull requests
* Expect reviews, feedback, iteration

---

## **Licensing Basics**

* **Permissive**: MIT, Apache — flexible, minimal restrictions
* **Copyleft**: GPL — requires sharing modifications
* Choose a license intentionally; respect project licenses
* Understand basics of copyright and patents

---

## **Sustaining an OSS Project**

* Good documentation
* Clear governance
* Healthy, inclusive community
* Consistent communication
* Managing conflict and preventing toxic behavior
* Use platforms like GitHub/GitLab to coordinate work

---

## **Key Tools & Skills**

* Git for distributed development
* CI/CD for testing and quality
* Issue trackers, pull requests, code review
* Community communication (mailing lists, chats, forums)

---

## **Core Mindset**

Open source succeeds through **people + process + transparency**.
Collaboration > control.
Community health = project health.
